# Gold Layer — Data Dictionary

The Gold Layer consists of two dimension views and one fact view, all living in the
`gold` schema:

- **`gold.dim_customers`** — one row per customer, enriched with demographics and geography.
- **`gold.dim_products`** — one row per product, enriched with category and pricing.
- **`gold.fact_sales`** — one row per sales transaction, ready to be sliced by any dimension.

All objects are **views** (not tables), so they always reflect the latest Silver data without a separate refresh step.

---

## 1. `gold.dim_customers`

**Purpose:** Stores customer details enriched with demographic and geographic data.

**Source:** `silver.crm_cust_info` + `silver.erp_cust_az12` + `silver.erp_loc_a101`

**Grain:** one row per customer (deduplicated by `cst_id`).

| Column Name | Oracle Data Type | Description |
|---|---|---|
| `customer_key` | `NUMBER(10)` | Surrogate key uniquely identifying each customer record in the dimension. Generated by `ROW_NUMBER()`. |
| `customer_id` | `NUMBER(10)` | Business key — unique numerical identifier assigned to each customer in the source system. |
| `customer_number` | `VARCHAR2(50)` | Alphanumeric business identifier (e.g. `AW00011000`), used for tracking and referencing. |
| `first_name` | `VARCHAR2(50)` | Customer's first name, cleaned and trimmed. |
| `last_name` | `VARCHAR2(50)` | Customer's last name or family name, cleaned and trimmed. |
| `country` | `VARCHAR2(50)` | Country of residence (e.g. `Australia`, `Germany`, `United States`). Falls back to `n/a` if missing. |
| `marital_status` | `VARCHAR2(50)` | Marital status, mapped from codes: `M → Married`, `S → Single`, otherwise `n/a`. |
| `gender` | `VARCHAR2(50)` | Gender. CRM is the master source; ERP fills gaps. Values: `Male`, `Female`, `n/a`. |
| `birthdate` | `DATE` | Date of birth (format `YYYY-MM-DD`). Nulled if implausible (e.g. future dates). |
| `create_date` | `DATE` | Date the customer record was created in the source system. |

**Business Rules Applied:**

- Duplicate `cst_id` rows are collapsed to the most recent record (`cst_create_date DESC`).
- Rows with `NULL` `cst_id` are dropped.
- `cst_gndr` takes priority over `gen` when both exist and differ.
- `country` and `gender` fall back to `n/a` when both CRM and ERP are missing.

## 2. `gold.dim_products`

**Purpose:** Stores product details enriched with category hierarchy and pricing data.

**Source:** `silver.crm_prd_info` + `silver.erp_px_cat_g1v2`

**Grain:** one row per **current** product (i.e. `prd_end_dt IS NULL`).

| Column Name | Oracle Data Type | Description |
|---|---|---|
| `product_key` | `NUMBER(10)` | Surrogate key uniquely identifying each product record. Generated by `ROW_NUMBER()` ordered by `prd_start_dt, prd_key`. |
| `product_id` | `NUMBER(10)` | Business key — unique numerical identifier from the CRM. |
| `product_number` | `VARCHAR2(50)` | Alphanumeric product code (e.g. `CO-RF-FR-R92B-58`), used for joining with the fact table. |
| `product_name` | `VARCHAR2(100)` | Product display name. |
| `category_id` | `VARCHAR2(10)` | Category prefix derived from the product key (`CO_RF`, `AC_HE`, etc.). |
| `category` | `VARCHAR2(50)` | High-level product category (e.g. `Bikes`, `Clothing`). |
| `subcategory` | `VARCHAR2(50)` | Subcategory within the parent category (e.g. `Road Bikes`, `Helmets`). |
| `maintenance` | `VARCHAR2(50)` | Whether the product requires maintenance (`Yes`/`No`). |
| `cost` | `NUMBER` | Product cost. Defaults to `0` when missing in the source. |
| `product_line` | `VARCHAR2(50)` | Product line, mapped from codes: `M → Mountain`, `R → Road`, `S → Other Sales`, `T → Touring`, otherwise `n/a`. |
| `start_date` | `DATE` | Date the product version became active. |

**Business Rules Applied:**

- Only currently-active products appear (`prd_end_dt IS NULL`).
- `cat_id` is derived by taking the first 5 characters of `prd_key` and replacing `-` with `_`.
- `prd_line` is mapped from single-letter codes to descriptive names.
- `cost` is coalesced to `0` when NULL.

## 3. `gold.fact_sales`

**Purpose:** Transactional sales data joined to dimensions via surrogate keys — ready for BI slicing.

**Source:** `silver.crm_sales_details` joined to `gold.dim_customers` and `gold.dim_products`

| Column Name | Oracle Data Type | Description |
|---|---|---|
| `order_number` | `VARCHAR2(50)` | Unique sales order number (business key). |
| `product_key` | `NUMBER(10)` | Foreign key to `gold.dim_products.product_key`. NULL if no matching product. |
| `customer_key` | `NUMBER(10)` | Foreign key to `gold.dim_customers.customer_key`. NULL if no matching customer. |
| `order_date` | `DATE` | Date the order was placed. Converted from an 8-digit numeric `YYYYMMDD` value in Silver. NULL if invalid. |
| `ship_date` | `DATE` | Date the order was shipped. Same conversion rule as `order_date`. |
| `due_date` | `DATE` | Date the order is due. Same conversion rule as `order_date`. |
| `sales_amount` | `NUMBER` | Total sales value. Recomputed as `quantity × |price|` when the source value is NULL, ≤ 0, or mathematically inconsistent. |
| `quantity` | `NUMBER` | Number of units sold. |
| `price` | `NUMBER` | Unit price. Recomputed as `sales_amount / quantity` when NULL or ≤ 0. Negatives are converted to positives via `ABS()`. |

**Business Rules Applied:**

- `sales_amount` is validated against the rule `sales = quantity × |price|`. Any row failing this rule is recomputed.
- `price` is never NULL, ≤ 0, or negative.
- Date columns are only populated when the source value is exactly 8 digits (e.g. `20101229`); otherwise NULL.
- `LEFT JOIN`s to dimensions preserve all sales rows — orphan rows appear with NULL `product_key` / `customer_key`.
